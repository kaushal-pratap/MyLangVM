# Getting Started

This guide walks you through installing, building, and running your first MyLangVM program.

---

## Prerequisites

You need two things:

1. **A C11-compatible compiler** — any of the following will work:
   - `gcc` (GCC 4.7+)
   - `clang` (Clang 3.1+)
   - Any compiler invocable as `cc` that supports `-std=c11`

2. **GNU Make** — used to orchestrate the build:
   - **macOS**: Comes pre-installed with Xcode Command Line Tools. Install them with `xcode-select --install` if needed.
   - **Linux**: Install via your package manager (e.g., `sudo apt install build-essential` on Debian/Ubuntu).
   - **Windows**: Use MinGW-w64 or MSYS2, which provide `make` (or `mingw32-make`) and `gcc`.

---

## Building the Project

### Clone the Repository

```bash
git clone https://github.com/kaushal-pratap/MyLangVM.git
cd MyLangVM
```

### Build Both Tools

From the project root, run:

```bash
make
```

This single command builds both components:
- **`build/assembler/mylangasm`** — the assembler
- **`build/vm/mylangvm`** — the virtual machine

The root `Makefile` delegates to the individual Makefiles inside `assembler/` and `vm/`. It also automatically creates the `build/` directory structure for you.

### Build Only the Assembler

```bash
make assembler
```

### Build Only the VM

```bash
make vm
```

### Using a Specific Compiler

The Makefiles respect the `CC` environment variable. To build with `gcc` explicitly:

```bash
CC=gcc make
```

## Running Your First Program

MyLangVM operates in two steps: **assemble**, then **execute**.

### Step 1 — Write a Program

Create a file called `my_first.asm` with the following contents:

```asm
PUSH 7
PUSH 3
ADD
PRINT
HALT
```

This program pushes `7` and `3` onto the stack, adds them, prints the result, and halts.

### Step 2 — Assemble It

The assembler takes two arguments: the input `.asm` file and the desired output path for the bytecode file.

```bash
./build/assembler/mylangasm my_first.asm build/bytecode/bytecode.mylangvm
```

If the assembly is successful, this produces a binary bytecode file at `build/bytecode/bytecode.mylangvm`. There is no output on success — silence means everything went well.

If there is an error in your program (for example, a misspelled instruction or a missing operand), the assembler will print a diagnostic with the line and column number:

```
Error: Integer missing
Line 1, Column 1
```

### Step 3 — Execute It

Feed the bytecode file to the VM:

```bash
./build/vm/mylangvm build/bytecode/bytecode.mylangvm
```

**Output:**

```
10
```

### One-Step Shortcut

The `mylang` shell script (in the project root) combines both steps:

```bash
./mylang my_first.asm
```

This assembles the file and immediately runs the resulting bytecode. It is equivalent to running the assembler and VM manually. Note that this script requires a POSIX-compatible shell (`sh`).

## Running the Included Examples

The `examples/` directory contains ready-to-run programs organized by category:

```
examples/
├── arithmetic/       add, subtract, multiply, divide, modulo
├── comparison/       equal, not_equal, greater_than, less_than, ...
├── control_flow/     jump, jump_if_zero, call_return, ...
├── demos/            calculator_demo, expression, memory_demo, stack_demo
├── io/               input, echo
├── memory/           store_load, overwrite
├── stack/            duplicate, pop, swap
└── unary/            negative, positive
```

Try any of them:

```bash
./mylang examples/demos/calculator_demo.asm
```

```bash
./mylang examples/control_flow/call_return.asm
```

```bash
./mylang examples/io/echo.asm
```

## Cleaning Up

To remove all build artifacts:

```bash
make clean
```

This deletes the compiled binaries and any generated bytecode files from the `build/` directory.

## Troubleshooting

| Problem | Solution |
|:---|:---|
| `make: cc: No such file or directory` | Install a C compiler. On macOS: `xcode-select --install`. On Ubuntu: `sudo apt install build-essential`. |
| `Permission denied: ./mylang` | Make the script executable: `chmod +x mylang` |
| `Error: Could not open program.asm` | Check that the file path you passed to the assembler is correct and the file exists. |
| `Unknown instruction` error at assembly time | Check spelling. All mnemonics must be valid (see the [Instruction Set Reference](04-instruction-set-reference.md)). The assembler is case-insensitive, so `push`, `PUSH`, and `Push` all work. |
| `Program terminated unexpectedly: missing HLT instruction?` | Every program must end with a `HALT` instruction. Add `HALT` as the last line. |
| `Stack Overflow !` | You are pushing more than 100 values without popping. The operand stack has a capacity of 100 elements. |
| `Stack Underflow !` | You are trying to pop from or peek at an empty stack. Make sure you have pushed enough values before performing operations. |
